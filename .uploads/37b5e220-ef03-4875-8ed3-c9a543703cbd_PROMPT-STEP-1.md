> 把下面整段内容复制给编程 Agent。它自带全部契约，不依赖本对话之外的上下文。

## 角色与目标

你是 DeepSeek Harness（下称 DSH）的插件工程师。在 `<workspace>/dsh-wiring/` 新建一个**可安装、可验证、零运行时依赖**的 DSH bundle，完成 Step 1：把官方已发布但没有任何 profile 挂载的 LSP 能力接上线，并提供一个只读的 `lsp_status` 诊断工具。

**只做 Step 1**：LSP（仅 TypeScript 一个语言服务器）。不要实现 browser、webhook、TTS、UI、配置页。

## 背景事实（已核实，不要重新调研）

- DSH 0.2.2-rc.1；`@deepseek-ai/dsh-lsp`、`dsh-lsp-stdio`、`dsh-tool-lsp` 已发布到 npm，但 `dsh-base` / `dsh-web-app` 的 patch 里**没有任何 lsp 行**，所以默认安装没有 `lsp` 工具。
- `dsh-lsp-stdio` 的配置形状：`servers` 是 record，键是 provider id，值为
  `{ command, args?, env?, extensionToLanguage, initializationOptions?, configuration?, maxMessageBytes?, maxStderrBytes?, maxDocumentBytes?, shutdownTimeoutMs?, killGraceMs? }`；
  `command` 必填（load 时解析，无 shell）、`extensionToLanguage` 必填；`servers` 至少一项。
  **一个实例内任一坏条目会让该实例全部 provider 回滚**，因此一行只放一个语言。
- `dsh-tool-lsp` 提供模型工具 `lsp`（operation = goToDefinition | findReferences | goToImplementation | hover）。
- Profile 的 `node_modules` 只装 bundle 自己，**宿主包不可从 bundle 解析**；因此源码禁止 import 任何 `@deepseek-ai/*`，也不要把宿主核心包写进 dependencies。

## 硬性约束（违反即返工）

1. **零运行时依赖**：`dependencies` 只允许三个官方 LSP 包（固定版本，见下），不允许其他；`devDependencies` 为空。
2. **零构建**：纯 ESM + JSDoc，不引入 TypeScript 编译、打包器、lint 工具链。
3. **禁止 import `@deepseek-ai/*`**（三个官方 LSP 包由 Loader 行挂载，不由源码 import）。
4. **禁止副作用**：`apply()` 不读文件、不联网、不写 profile、不调用 `configEditor`、不 `console.log`。
5. **禁止写 profile**：不要修改 `$DSH_HOME` 下任何文件，不要安装 bundle（安装需要人工审批，不在本任务内）。
6. **不碰兄弟目录**：不要修改 `<workspace>/awakening-layer/`（那是上一版参考实现，可读来对照，不可改）。
7. **工具定义手写**：`parameters` 用原始 JSON Schema；`output` 必填（`schema` + `render`）；不要 import `defineTool`。
8. 所有新增文件用 UTF-8；缩进 2 空格；LF。

### src/index.js（引擎，约 130 行）

导出：

```js
export async function runChecks(ctx, checks, options)   // Promise<CheckResult[]>
export function defineStatusTool(ctx, capability, options) // ToolDefinition
export function formatReport(capability, report)        // string
export function apply(ctx)                              // 遍历 capabilities 注册
```

- `options = { timeoutMs = 1500 }`。
- `Check.kind`：`command`（`ctx.subprocess.resolveExecutable(command, undefined, signal)`）、`path`（`node:fs` 的 `existsSync`）、`service`（`ctx.get(service) !== undefined`）。
- 每个检查：独立 `AbortController` + 超时竞速；`try/catch` 全包；结果 `{ id, label, ok, detail, install }`。
- `detail` 单行且截断到 160 字符；取值固定为 `'mounted'`、`'service unavailable'`、`'not found on PATH'`、解析到的绝对路径、`'timeout'`、`'error: <message>'`。
- `defineStatusTool`：`name = ${capability.id}_status`；`description` 固定模板（说明「报告本机是否具备该能力、缺什么、装什么」+「在依赖该能力前或失败后调用」）；`parameters = { type:'object', properties:{}, additionalProperties:false }`；`execute` 先 `runChecks` 再组装 report，**永不 reject**；`output.schema` 严格如下，`output.render` 返回 `[{ type:'text', text: formatReport(...) }]`。

```js
{
  type: 'object',
  properties: {
    capability: { type: 'string' },
    ok: { type: 'boolean' },
    checks: {
      type: 'array',
      items: {
        type: 'object',
        properties: {
          id: { type: 'string' }, label: { type: 'string' },
          ok: { type: 'boolean' }, detail: { type: 'string' }, install: { type: 'string' }
        },
        required: ['id', 'label', 'ok', 'detail', 'install'],
        additionalProperties: false
      }
    },
    next: { type: 'string' }
  },
  required: ['capability', 'ok', 'checks', 'next'],
  additionalProperties: false
}
```

- `apply(ctx)`：`for (const capability of capabilities) ctx.effect(() => ctx.tools.register(defineStatusTool(ctx, capability, { timeoutMs: 1500 })))`；模块级无状态。
- `inject = ['subprocess', 'tools']`。

### test/engine.test.mjs

用 `node:test` + `node:assert/strict`，构造假 ctx（`tools.register` 收集定义、`effect` 立即执行、`subprocess.resolveExecutable` 可注入、`get(name)` 返回对象或 undefined）。至少覆盖：

1. **R1 惰性**：`apply()` 后 `resolveExecutable` 调用次数为 0。
2. **R2 超时**：注入永不 resolve 的解析器，`timeoutMs: 50` 时该项 `detail === 'timeout'`，其余项不受影响。
3. **R3 不抛**：解析器直接 throw 时仍得到完整 report。
4. **R4 幂等**：disposer 调用后，再次 `apply` 仍只注册一份。
5. **R7 降级**：`get('lsp')` 返回 undefined 时 `seam` 项 `ok:false`、`detail:'service unavailable'`。
6. **报告形状**：`ok` 等于所有项 `ok` 的与；`next` 等于第一个失败项的 `install`；全部通过时 `next === ''`。
7. **schema 校验（可跳过）**：尝试 `import('@deepseek-ai/dsh-tools')`，失败则从 `%APPDATA%/npm/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-tools/lib/index.js` 以 `pathToFileURL` 解析；拿到后用 `assertSupportedJsonSchema(tool.parameters)`、`assertSupportedJsonSchema(tool.output.schema)`、`validateJsonSchemaValue(tool.output.schema, report)` 断言无问题。拿不到时打印一行 `skip: validator unavailable`，不失败。

### test/lsp.test.mjs

1. 描述符不变量：`id === 'lsp'`、`blastRadius === 'tool'`、`defaultEnabled === true`、每个 check 有 `id/label/kind`。
2. `defineStatusTool` 产出名为 `lsp_status`，`parameters.type === 'object'`。
3. 两种 ctx（解析成功 / 解析失败）下 `execute` 的 `ok` 与 `next` 正确，且 `execute` 不抛。
4. `formatReport` 输出含每个 check 的 label 与失败项的 install 命令。

### scripts/check.mjs

无依赖、可独立运行，失败退出码 1。检查：

1. `package.json`：`name`、`type: module`、`dsh.bundle.patch === './cordis.patch.yml'`、`exports['./icon']`、`exports['./locale/*.json']`、`engines.dsh`、`files` 含 `src` 与 `cordis.patch.yml`。
2. locale：`en` 与 `zh` 都能 JSON.parse；`meta.title`、`meta.description`、`capabilities.lsp.title` 非空。
3. `icon.svg`：大小 < 8 KiB，trim 后以 `<svg` 开头、`</svg>` 结尾。
4. `cordis.patch.yml`：无 tab；首个非注释行是 `- insert:`；行 id 唯一且全部以 `wiring-` 开头；至少 4 行。若能从 `%APPDATA%/npm/node_modules/@deepseek-ai/dsh/node_modules/js-yaml/index.js` 加载 `js-yaml`，则真实解析并断言顶层为数组、每行有 `id`/`name`。
5. **R5**：`src/**/*.js` 不出现 `configEditor`、`writeFile`、`appendFile`、`mkdir`。
6. **R6**：`src/**/*.js` 不出现 `from '@deepseek-ai/` 与 `import('@deepseek-ai/`；`dependencies` 只含三个允许的官方 LSP 包。
7. **R8**：`import` 每个 `src/capabilities/*.js`，若 `blastRadius !== 'tool'` 则要求 `defaultEnabled === false` 且 patch 文本含 `disabled: true`。

输出格式：每个包一行 `ok ...`，最后 `PASS` 或逐条 `FAIL` + 退出码 1。
